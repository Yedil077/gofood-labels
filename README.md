# GOFOOD — печать этикеток блюд (веб на Netlify + Print Agent для Epson CW-C4030)

Веб-сайт для кухни: найти блюдо → превью этикетки **80 × 50 мм** (Макет 1 / Макет 2) → количество → «Печать» →
физическая этикетка на **Epson ColorWorks CW-C4030** (USB) без ручной настройки каждый раз.

```
┌──────────────────────── Netlify (netlify.app) ────────────────────────┐
│  web/           React SPA — статика (превью этикетки рисуется в браузере) │
│  netlify/functions/api.js   один роутер /api/*                           │
│  Netlify Blobs              данные: блюда, настройки, история, логи, очередь│
└───────────────────────────────▲──────────────────────────────────────────┘
                                │ HTTPS (опрос очереди + статус)
┌───────────────────────────────┴──────────── Windows PC (принтер по USB) ─┐
│  print-agent/   Node-агент: раз в ~2 c берёт задание из облака,           │
│                 рисует PNG (тот же код, что в браузере) → PDF точного      │
│                 размера → pdf-to-printer (SumatraPDF, noscale) → Epson     │
└──────────────────────────────────────────────────────────────────────────┘
```

Браузер на Netlify (HTTPS) не может печатать на USB-принтер — поэтому на ПК с принтером работает
маленький **Print Agent**. Он же — единственное, что нужно «поставить на винду».

---

## 1. Публикация веб-сайта на Netlify

1. Залейте папку `gofood-labels/` в Git-репозиторий (GitHub/GitLab/Bitbucket).
2. Netlify → **Add new site → Import an existing project** → выберите репозиторий.
   `netlify.toml` уже настроен (build = `cd web && npm install && npm run build`, publish = `web/dist`,
   функции = `netlify/functions`).
3. **Site configuration → Environment variables** — добавьте:

   | Переменная | Значение | Зачем |
   |---|---|---|
   | `GOFOOD_TOKEN` | придумайте длинную строку | пароль администратора (импорт, правка, настройки, тест-печать) |
   | `GOFOOD_AGENT_TOKEN` | придумайте другую строку | пароль Print Agent (опрос очереди) |

   Если переменные не заданы — API работает без пароля (только для проверки, не для продакшена).
4. **Deploy**. Netlify Blobs включается автоматически, отдельная БД не нужна.
5. Откройте выданный адрес `https://ваш-сайт.netlify.app`.

## 2. Первая настройка через сайт

1. **Администратор → Настройки и печать → Подключение** → вставьте `GOFOOD_TOKEN`
   (хранится только в вашем браузере).
2. **Импорт Excel** → загрузите `Блюда … .xlsx`. Файл читается прямо в браузере; берутся строки
   `Тип = «Блюдо»`, строки «Группа» становятся категориями.
3. **Настройки** → «Часовой пояс кухни» (Алматы = `300` минут от UTC), при необходимости — размер
   этикетки, символика штрихкода, слоган, условия хранения. Сохранить.

## 3. Print Agent на ПК с принтером (Windows)

1. Скопируйте папку `gofood-labels/` на этот ПК (нужна подпапка `print-agent/` и `web/src/shared/`).
2. В `print-agent/` скопируйте `agent-config.example.json` → **`agent-config.json`** и заполните:

   ```json
   {
     "apiBase": "https://ваш-сайт.netlify.app",
     "agentToken": "тот же GOFOOD_AGENT_TOKEN",
     "pollMs": 2000,
     "printerName": "",
     "dryRun": false,
     "name": "kitchen-pc"
   }
   ```
   `printerName` можно оставить пустым — принтер выбирается на сайте (Настройки → Принтер).
3. Запустите **`print-agent/START-AGENT.bat`** (первый раз поставит зависимости — нужен интернет).
   Не закрывайте окно во время работы кухни.
4. На сайте (Настройки → Подключение) индикатор станет **🟢 на связи**, в списке принтеров
   появится **EPSON CW-C4030** — выберите его и сохраните.

**Автозапуск:** ярлык на `START-AGENT.bat` положите в
`shell:startup` (Win+R → `shell:startup`), либо создайте задачу в «Планировщике заданий»
(триггер «При входе в систему»).

## 4. Драйвер Epson CW-C4030 (один раз)

Обнаруженная модель на ПК — `EPSON CW-C4030`. Этикетка — **80 × 50 мм**, макет альбомный
(ширина 80, высота 50); сайт печатает страницу `@page { size: 80mm 50mm; margin: 0 }`.

1. Windows → «Принтеры и сканеры» → **EPSON CW-C4030** → «Настройка печати».
2. **Media Settings**: Media Type = *Die-cut Label* (вырубная этикетка, как загружена);
   **Media Size → пользовательский размер 80 × 50 mm** по рулону (если драйвер задаёт
   «ширина × длина» по ленте — введите ширину ленты и шаг этикетки как на рулоне, например
   `50 × 80` при подаче узкой стороной; ориентацию затем выставить «Альбомная»).
   Сохранить по умолчанию.
3. В диалоге печати браузера: принтер EPSON CW-C4030, «Размер бумаги» — созданный 80 × 50,
   **«Поля» = Нет**, **«Масштаб» = 100 %** (не «Вписать»), колонтитулы выключены.
4. На сайте: **Настройки → Тестовая печать** — калибровочная этикетка с линейкой (метки
   каждые 10 мм): проверьте, что 80 мм по ширине и 50 мм по высоте, ничего не обрезано.

Агент печатает PDF ровно в размер страницы с `scale = noscale` — размер носителя задаёт драйвер.
Носитель ≥ 95 × 65 мм (старый 100 × 70) по-прежнему рисуется классическим макетом.

Агент печатает PDF ровно в размер страницы с `scale = noscale` — размер носителя задаёт драйвер.

## Локальная разработка

```bash
npm install            # ставит netlify-cli и @netlify/blobs в корне
npm run dev            # netlify dev: web (Vite) + функции + Blobs-песочница на http://localhost:8888
npm test              # node --test: 16 тестов, включая 6 контрольных примеров даты/времени из ТЗ
```

Print Agent локально: в `agent-config.json` укажите `"apiBase": "http://localhost:8888"`,
`"dryRun": true`, затем `npm run agent`.

## Данные из Excel (что определено при анализе)

Источник — `Блюда 03.09.2026 09.20.21.xlsx` (лист «Блюда»):

| Поле | В Excel | Использование |
|---|---|---|
| Название (кол. D) | да | название блюда (автоперенос + автоуменьшение шрифта, до 3 строк) |
| Иерархия A/B/C | да | **C** = категория-группа («Горячее из говядины», «Салаты», …) |
| Артикул | да, уникальный | альтернативный источник штрихкода |
| **Код** | да, 4 знака, уникальный | **источник штрихкода по умолчанию** (не генерируется) |
| Тип | «Группа» / «Блюдо» | печатаются только `Тип = Блюдо` |
| **Состав** | **нет** | вводится в админке, не выдумывается |
| **КБЖУ** | **нет** | вводится в админке, не выдумывается |

Категория = ближайшая группа левее колонки блюда. `category_source`: `excel` / `uncertain` / `none`
(последнее — ручной выбор в «Блюда»). Повторный импорт — upsert по `Код`, **сохраняет** ручные
правки (состав, КБЖУ, ручную категорию).

## Дата/время на этикетке — `calculateLabelDateTime()`

[`web/src/shared/labelDateTime.js`](web/src/shared/labelDateTime.js) — изолирован от UI, БД и сети,
используется и функцией, и агентом.

- **Дата** выводится из 6 контрольных примеров ТЗ однозначно: смена «катится» в следующий день
  в **09:00** (настраивается). Все 6 примеров проходят.
- **Время** из 6 примеров **однозначно не выводится** → формула **не придумана**. Механизм:
  таблица контрольных примеров (точное совпадение → точный вывод, редактируется в
  Настройки → Дата/время) + «запасное правило» с пометкой «приблизительно». Когда бизнес даст
  формулу — вносится туда, остальной код не меняется.
- Часовой пояс кухни: `datetime.tzOffsetMin` (Алматы = 300). Браузер шлёт своё локальное время;
  для тест-печати агентом используется смещение из настроек.

## Хранилище (Netlify Blobs, store `gofood`)

`settings` · `dishes` (массив) · `batches` · `logs` (последние 500) · `job/<id>` (по блобу на
задание печати — очередь и история). Файлы PDF на печать сохраняются агентом в `print-agent/out/`.

## Бизнес-правила (ТЗ п.20)

Не выдумывать отсутствующие данные · не менять коды и названия из Excel · не генерировать
случайные штрихкоды · категорию менять только с указанием источника (`manual`).

## Ограничения версии

- Веб-сайт и агент требуют интернет (Netlify). Полностью офлайн-режим (локальный сервер вместо
  облака) в этой версии не входит — при обрыве связи агент повторяет попытки, печать
  возобновится автоматически после восстановления сети.
- QR-код в превью не рисуется (рисует агент); линейные штрихкоды (CODE128/39, EAN-13) — в превью и на печати.
